# DuoPress — ребрендинг

## Цель

Переименовать Double Power Key в **DuoPress**. В лаунчере оставить только имя; в документации RU/EN описать назначение: «Двойное нажатие кнопки питания на vivo и iQOO с OriginOS». Не заявлять поддержку FuntouchOS и не выдавать DuoPress за продукт vivo. Новых проверок модели или прошивки в коде не добавлять.

## Подход

- **Новая установка — выбрано.** Новый `applicationId` и Kotlin/Gradle namespace: `com.krayapp.duopress`. Debug сохраняет суффикс `.debug`. Старая версия может остаться установленной, но настройки, выбор обработчика Vivo и разрешение Shizuku не переходят автоматически. Если Vivo уже запускает старую версию, пользователю нужно выбрать DuoPress в системе.
- **Обновление поверх старой версии — отклонено.** Сохранение `com.vivotomirpay.stub` упростило бы перенос данных, но не дало бы отдельной установки.

Основа — текущий коммит ветки `refactor/kotlin-compose-mvi` (`1d8f32b`). Ребрендинг изолировать в отдельной ветке; локальные незакоммиченные изменения слайда не переносить и не модифицировать.

## Имя и иконка

- Имя **DuoPress** одинаково в RU/EN: лаунчер, окно выбора обработчика Vivo, заголовки и упоминания в интерфейсе. Обновить также имя Gradle-проекта, баннеры скриптов сборки и README.
- Цветной знак — выбранный эскиз **C «Боковая кнопка»**: белый контур телефона со скруглёнными углами, выделенная кнопка на правой грани и два коротких штриха справа, обозначающих два нажатия. Плоский синий фон `#415FFF`, без логотипа vivo, букв и мелких деталей. Весь знак помещается в центральную безопасную область adaptive icon.
- Тот же силуэт на прозрачном фоне — слой `<monochrome>` для лаунчеров с тематическими иконками. Цветная adaptive icon — для API 26+, цветной fallback — для API 25.

## Границы изменения

Перенести пакеты приложения и тестов, обновить имена компонентов и внутренние ссылки, производные от идентификатора приложения. Сохранить подпись, минимальную версию Android, формат настроек, Vivo action, его метаданные и ограничения Shizuku. Не добавлять разрешения или миграцию данных, не менять поведение действий или навигации. Репозиторий GitHub и опубликованные релизы не переименовывать.

## Проверка

Собрать debug и release, прогнать JVM-тесты, lint и доступные инструментальные тесты. Проверить в APK новые идентификаторы, неизменную подпись и набор разрешений с учётом переименованных идентификаторов, разрешение Vivo-интента и ресурсы обеих иконок. На эмуляторе проверить отдельную установку рядом со старой и запуск нового пакета; физическое двойное нажатие подтверждается только на vivo/iQOO с OriginOS.
